# UI Design Patterns

UI design patterns, as explained in the Interaction Design Foundation’s article on UI Design Patterns, are a key tool. These patterns are like reusable solutions for common interface problems, and they’re usually found in UI toolkits or guidelines. They’re super helpful because they’re already tested, but you’ve got to make sure they fit the project’s needs. In our system for managing medical records, I realized there’s a pattern we didn’t use in our prototype but should have, as it would’ve made the interface more useful and user-friendly.

Luis is a psychologist with 8 years of experience who oversees therapists in training and needs to ensure that clinical records are complete and well-documented. His main pain is the lack of control over incomplete records and the difficulty in monitoring documentation progress. A UI pattern we should’ve applied is the Dashboard, which displays key information visually and concisely, letting the user oversee important data at a glance.

Not including this pattern was a mistake, as it would’ve supported the project’s usability goals. A Dashboard would’ve given Luis a clear and immediate view of the clinic’s status, reducing his frustration and improving his ability to coordinate. UI and UX need to solve real problems, and using Personas like Luis helps us figure out which patterns are necessary. I now understand that patterns like the Dashboard don’t just make the interface more organized, they transform how busy users like Luis interact with the system, saving them time and effort.
